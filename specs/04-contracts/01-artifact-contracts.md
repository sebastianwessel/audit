# Artifact contracts

All CLI inputs, model outputs, tool inputs/outputs, and persisted artifacts are strict Zod schemas owned by their feature under src/features/. Universal primitives belong under src/shared/contracts/. Types come from z.infer. Closed enums are normalized from case/whitespace variants at the boundary; unknown keys and values fail. Per-field text validation protects a boundary but must never silently cap an approved source/context corpus, range, search result, workflow traversal, complete tool glob set, source path, lineage entry set, evaluator result/readiness collection, or evaluator-only acquisition metadata collection. Safe path validation is single-owned by the shared relative-path schema and permits every non-empty slash-delimited relative path without traversal, backslashes, or NUL. Finite closed-enum projections may be structurally exact; they are not evidence ceilings.

## Configuration

Each CLI command validates its own closed option set before loading configuration, opening a root, reading an artifact, constructing a provider, or dispatching a model. Unknown and command-incompatible options fail as invalid input; no option is silently ignored. It then validates target, output, context, source-admission policy, and limit arguments at its own boundary. Target, context, and output roots are canonical non-symlink directories that are pairwise disjoint before any I/O other than root canonicalization. Output is neither equal to nor an ancestor/descendant of target or context. The v1 target network policy is always deny; no plan or model can change it. The platform RuntimeConfigurationSchema contains the optional primary provider, model, and API-key environment-variable name plus artifact/evaluation paths and maxParallelVectors (1..8). Provider is openai or anthropic when configured. Cost pricing resolves only from the generated bundled catalogue using an exact normalized provider/model pair; unknown entries yield a visible `unavailable` cost result rather than a zero estimate. Price values are not runtime configuration.

Local runtime defaults are loaded only by the platform configuration adapter from an optional project-root `.env`. Its closed configuration shape contains optional provider, model, and API-key environment-variable name plus artifact and evaluation paths. `verificationMode` is `same-route` by default or an evaluation-only `independent-route`. The latter requires a complete distinct verifier provider/model pair and a named secret environment variable; it never stores the secret value. Incomplete or equivalent normalized route pairs fail before target I/O. Product commands reject this experimental mode. Precedence is built-in defaults, inherited environment, `.env`, then explicit CLI flags. Empty values mean unset. The loader validates dotenv syntax, does not log values, and does not persist credentials in any artifact.

`ContextDocumentSchema` requires a relative path, title, `kind`, sensitivity, applies-to globs, Markdown body, and content digest. `kind` is one of `architecture`, `deployment`, `data-flow`, `controls`, `threat-model`, or `other`; sensitivity is `public`, `internal`, `confidential`, or `restricted`. The frontmatter parser rejects unknown keys, duplicate keys, malformed delimiters, unsupported YAML constructs, invalid globs, and non-UTF-8 content. It preserves the Markdown body byte-for-byte after the frontmatter delimiter, including leading/trailing whitespace and line-ending form; only an all-whitespace body is invalid. There is no fixed context-document count, metadata-list, or body-size ceiling. Context discovery accepts the `.md` extension case-insensitively. A provider-signalled context recovery chunk preserves the exact concatenation of its original body; it may not trim or normalize line endings. Body text is never interpreted as executable instructions.

The validated target inventory contains sorted context documents and a context digest. The planner and auditor receive context documents in a separate labeled section from source evidence. Context may explain a claim or identify a security control, but source evidence remains required for a finding and context cannot change permissions, approval status, network policy, or scope.

## Snapshot and plan

`SourceAdmissionPolicySchema` owns named include/exclude policy and default-exclusion reasons. It rejects arbitrary maxima for files, bytes, lines, matches, context bodies, or tools. `SourceSnapshotManifestSchema` contains sorted manifest rows and the derived target fingerprint. Each row is either one admitted regular UTF-8 file with normalized relative path, byte length, content digest, and private snapshot-object reference, or one excluded entry with a closed reason. A source snapshot is built through exact streaming byte transactions; it never concatenates the corpus or rereads mutable target content after its digest is accepted. Context is separately digested and preserves line endings. Publication of private source/context objects and the target-keyed `SourceSnapshotRetentionIndexSchema` mutation use the same exclusive lease; release uses that same lease and removes the snapshot directory only after the final run/context owner is removed.

## Plan

AttackPlanSchema requires schemaVersion, planId, planDigest, target snapshot identity, context digest, createdAt, inventorySummary, and vectors. target is rootFingerprint plus bounded displayName. Human plan review, ownership, approval, and change-management records are external to the product and are not accepted in this contract. inventorySummary is a projection of the snapshot manifest.

AttackVectorSchema requires vectorId, vectorDigest, title, rationale, enabled, scopeGlobs, explicit risk-positive reviewObligations, and limitations. Its title is only a human-readable review focus; it is neither a taxonomy label nor an urgency judgment. A review obligation has a stable obligationId, riskStatement, and evidenceRequirement; its id is unique inside the vector. Each vector has at least one obligation. `vectorDigest` is SHA-256 over every behavior-affecting vector field; `vectorId` is its stable projection. `planDigest` is SHA-256 over canonical plan behavior plus target snapshot and context identity; `planId` is its stable projection. Timestamps and display metadata do not affect either digest. Duplicate vector IDs/digests, duplicate obligation IDs, and zero enabled vectors fail. Human editing requires explicit validate/reseal and always produces a new identity. scopeGlobs are evaluated against normalized admitted snapshot paths; an empty match is a visible execution state, never an unrestricted fallback or deterministic clean result. Retired category and priority fields are rejected rather than converted.

`SourceEvidenceRoleSchema` is single-owned by attack planning and reused by report, investigation, and verification contracts. Its values are `entrypoint`, `operation`, `unsafe-condition`, `source`, `sink`, `guard`, `dataflow`, `root-control`, and `counterevidence`; all are normalized model tokens and organize source-backed explanation only. Evidence-map facts use their own neutral role vocabulary, which additionally permits `entrypoint` beside input, asset, boundary, operation, control, output, and assumption. No contract creates or admits a synthetic origin-to-operation path: role labels and explicit map references organize provenance only and are never security proof.

`AuditReportLineageSchema` is a strict schema version 2 owned by `audit-lineage/`. It has `lineageId`, `generatedAt`, previous/current report identities (`reportId`, `planId`, `targetFingerprint`), aggregate status counts, and a complete sorted entry list with no product cardinality ceiling. An entry has opaque `findingIdentity`, nullable prior/current scan-local `findingId`, nullable prior/current `vectorId`, a `new|persisting|resolved|unknown` status, and an exact closed reason token. Its identity is a source-free partial fingerprint over vector, approved obligations, evidence roles/paths/kinds, and evidence-content hashes. It intentionally excludes model claim wording and absolute line numbers; a collision is rejected rather than guessed. It contains no source path, source snippet, statement, limitation, prompt, model output, tool result, or credentials. Reports must reject duplicate coverage vector IDs and duplicate deterministic finding IDs so lineage never arbitrarily selects an input record.

The model produces one executable plan. The product does not define approval, draft, rejected, reviewer, or review-note fields.

## Evidence, finding, report

Evidence requires relative path, positive startLine, optional endLine not below startLine, bounded snippet, and kind source, configuration, context, or inventory. Every persisted or rendered source-derived snippet and model-authored free-text field must pass through the single safe-artifact projection before persistence: it redacts recognized secrets and personal identifiers and removes terminal/control characters without truncating approved source evidence. Evidence must resolve inside the jail and be safely redacted before persistence.

`EvidenceMapSchema` holds neutral source-backed facts, controls, unanswered obligations, and limitations for one vector; it is neither a finding nor a deterministic security rule. Its model-facing candidate is a closed bounded untrusted map: a fact carries a schema-valid identifier, closed neutral role, bounded statement, plan references, and one-or-more exact `{path,startLine}` selections. It also carries exactly one `controlCoverage` entry per approved obligation. Each entry lists the distinct `controlFactIds` that the mapper associated with that obligation. Every downstream map-fact reference collection and unanswered-obligation collection is a unique set: a duplicate cannot replace a required fact through length or membership comparisons. In a canonical map, an obligation is either mapped or unanswered, never both. Model-bound overlap is normalized only by discarding the unanswered declaration after a retained validated fact maps that same obligation; it never persists a contradictory state. Map integrity validates each selection against the scoped source, then projects the canonical redacted snippet, kind, and one-line range; it quarantines a fact with an invalid plan, duplicate identifier, path, or line and fails coverage when an entry is missing or does not exactly match the retained neutral control facts. It cannot carry a snippet, source kind, evidence role, or end line, and it cannot persist model-authored provenance metadata. The stage never promotes an unrecognized role or an out-of-plan reference by normalization. `SourceEvidenceSchema` is the sole owner of persisted source-evidence kind, role, and optional end-line representation. It applies the shared model-token normalization and explicit optional-null normalization at canonical model boundaries, then persists only canonical lowercase tokens and omitted optional values; mapping, investigation, and verification never implement separate formatting rules.

Every persisted obligation-closure row binds its repeated obligation identifier to the same canonical plan reference. Its map state, fact count, posture conclusion/reason, candidate count, admitted-finding count, and terminal disposition must be mutually consistent. Vector coverage then conserves these rows: map facts are bounded by the closure references that retain them, unanswered and posture counters equal their closure projections, admitted findings are represented by a closure, and the admission funnel equals the vector finding count when present. A vector result must exactly match its persisted finding and review-required arrays; a report must exactly match each coverage row to same-vector report entries and may not retain an entry for an uncovered vector. These are provenance and artifact-integrity checks only; they never infer a risk, source flow, exploitability, severity, or control effectiveness.

`SourcePostureSchema` is the sole shape for one candidate-blind conclusion (`risk-supported`, `risk-contradicted`, `inconclusive`, or `not-applicable`) per approved review obligation. A `not-applicable` conclusion carries a crisp required reason and is neutral: it is neither a finding nor a passed check. Every other conclusion omits that reason. Its cited map facts must include every retained neutral `control` fact for that same obligation; this forces an explicit candidate-blind control challenge without deciding effectiveness deterministically. A discovery seed is non-reportable and carries only exact vector/obligation identity, map facts, posture assessments, a bounded hypothesis, and limitations. Grounding returns exactly one paired null or candidate per seed, and a candidate must preserve that identity. A model-facing non-null candidate carries `operationEvidence` and `unsafeConditionEvidence` selections, each a model-normalized selected map `factId` plus a bounded evidence index; it cannot carry free-form candidate evidence. Both selected facts and posture assessments must bind the candidate's complete approved-obligation set. The grounding identity module projects the corresponding canonical source evidence and roles. `UnverifiedAuditVerificationResultSchema` applies the same closed handoff to the verifier: an accepted output selects operation, unsafe-condition, control, obligation-reconciliation, and posture-reconciliation evidence by map `factId` and bounded index. Its canonical materializer derives the exact hypothesis obligations, relevant `control` fact identifiers, and every candidate-relevant posture assessment. An obligation reconciliation is one closed `supports-claim`, `contradicts-claim`, or `unresolved` model judgment for each exact human-approved plan obligation, with a non-empty selection from map facts bound to that exact obligation. A posture reconciliation has the same closed disposition and a non-empty selection from that assessment's map facts. Only complete reconciliation sets without `unresolved` may materialize an accepted result. These checks validate provenance, coverage, and declared state only and do not infer data flow, vulnerability semantics, or control effectiveness. `AuditEvidenceMapDraftSchema` and `AuditSourcePostureDraftSchema` persist their validated/redacted phases. Candidate-grounding draft v4 persists only canonical grounded candidates, validated closures, the complete source-free discovery-to-grounding funnel, the complete canonical-candidate rejection ledger, and content-free discovery/grounding observations; a resumed verifier must project those same ledgers and observations into its terminal coverage. Discovery seeds and raw grounding output never persist. `AuditVerificationResultSchema` is exactly `accepted`, `rejected`, or `incomplete`. Accepted requires reconciled `operation` and `unsafe-condition` locations, the exact complete set of hypothesis plan obligations, an exact complete source-backed obligation-reconciliation set, a source-backed control assessment, explicit `consideredEvidenceMapFactIds` coverage for every mapped `control` fact sharing those obligations, and one materialized posture reconciliation for each posture assessment relevant to the obligations. For each listed mapped control, obligation, or posture assessment, the assessment evidence must overlap at least one source location recorded by its corresponding map fact; the check proves inspection provenance only and never determines whether the control or posture is effective.

AuditReport v15 carries source-free discovery-to-grounding attrition beside the closure matrix. Its conservation rule is discovered seeds = discovery-binding rejections + grounding nulls + grounding binding rejections + submitted candidates. It carries aggregate counts keyed only by separate closed discovery-seed and canonical-candidate structural-rejection enums, so a failed generic contract boundary can be measured without retaining seed, candidate, or source content. A candidate and persisted finding contain only a precise statement, approved obligations, selected source evidence, and limitations; category, priority, confidence, impact, and proposed fix are absent. A persisted report item is either `accepted` with `verified` evidence or `needs-review` with `insufficient-evidence`; no legacy candidate/dismissed item or inferred cross-finding chain is representable. Both its own and every terminal vector result's required `reviewRequired` collection are distinct from `findings`: every item is redacted and cannot share an identifier with an accepted finding. It represents a structurally accepted candidate-aware result that conflicts with relevant candidate-blind posture and never contributes to CI finding status. Audit reports v1–v14 and terminal checkpoints v1–v11 are rejected rather than reinterpreted as this contract.

`AuditCheckpointBindingSchema` binds run ID, exact plan/vector digests, target snapshot/context identity, provider/model/verifier route, phase, and every applicable prompt/tool protocol fingerprint. A terminal checkpoint additionally binds the aggregate of its contributing phase protocol fingerprints. A map draft is reusable only to retry posture, discovery, grounding, or verification; a posture draft only to retry discovery, grounding, or verification; a candidate-grounding draft only to retry verification; a terminal result only after all binding values match. Grounding reuse additionally requires the complete prompt-protocol fingerprint. A context-overflow topology ledger additionally binds its reducible phase, stage id, root scope hash, and recovery-protocol fingerprint. Its ordered event history contains only opaque child identities, per-dispatch attempt numbers, scope hashes, closed transition states, stable error codes, timestamps, and one optional terminal-child content-free model observation. `AuditEvidenceMapRecoveryLeafSchema`, `AuditSourcePostureRecoveryLeafSchema`, and `AuditCandidateGroundingRecoveryLeafSchema` bind that same identity plus their parent stage, recovery protocol, root scope, child identity, and child scope hash. Map/posture leaves hold only validated redacted phase data. A grounding leaf holds exactly one canonical `grounded`, `null`, or `binding-rejected` result per ephemeral seed after source validation; it holds neither the seed nor raw model selectors. Every leaf is written before the matching topology completion event and is reusable only when that matching completed event exists. No topology or leaf artifact persists paths, ranges, context digests/bodies, prompts, tool data, source, or raw model output. Discovery seeds and raw grounding output are not artifacts. Older versions cannot be silently reused.

Where prior contract prose names older report/checkpoint artifacts, this registry's v15/v13 versions govern. Earlier versions are historical only and are rejected at the boundary.

`ModelStageObservationSchema` includes `evidence-mapping`, `source-posture`, and `candidate-grounding` alongside planning, investigation, verification, and countercheck. Every stage remains source-free and its aggregate usage/cost derives from its request ledger.

Runtime observations use `catalogue` only when the generated snapshot has an exact normalized provider/model entry; otherwise they use `unavailable`. Ad-hoc price configuration is rejected. The updater downloads the external catalogue only through the explicit contributor command, never during a product audit, plan, report, or provider evaluation.

## Read-only tool shapes

`repo_list` input is includeGlobs and excludeGlobs; output is complete sorted admitted snapshot entries with relative path, sizeBytes, and optional languageHint. `repo_read` input is relative path, optional startLine, and optional endLine; output is the complete requested snapshot range or a safe cursor page that identifies the exact remaining range. `repo_grep` input is pattern, mode literal/identifier/regex, caseSensitive, and optional relative paths; output is complete scoped snapshot matches or a safe cursor page that identifies the exact remaining search transaction. Identifier mode matches only language-neutral identifier boundaries. The review-workflow tool-contract module is the single model-facing owner for all three shapes and descriptions. Every tool object is strict and every output is validated before the model sees it. A stage records aggregate file-tool usage but has no fixed product call or return cap that can omit approved evidence. Execution budgets contain only run timeout, model timeout, and retry mode; unknown fields are rejected.

Markdown is a deterministic projection of validated JSON. It renders every persisted finding-evidence record with its role, location, and safely projected snippet; it may not select only a primary evidence item. Operational rows are complete and deterministically ordered rather than truncated to a presentation count. Every artifact carries a schema version. Claim-first reports are v15, terminal checkpoints v13, canonical grounding drafts v4, and lineage artifacts v2; all earlier plan/report/checkpoint artifacts are rejected rather than translated.

## Evaluation contracts

`EvaluationPackSchema` requires a pack id/version, supported track, fixture roots, case ids, provenance entries, license status, and a digest of the answer-key directory. `EvaluationCaseSchema` requires a case id, language, difficulty, fixture path, expected locations or location ranges, and adjudication notes. The model-facing target view is generated without expected fields and is validated as a separate `EvaluationAgentInputSchema`.

`CorpusCandidateRegistrySchema` is a separate strict, digest-bound acquisition contract. Its source record and each candidate contain only repository URL, vulnerable/patched revisions, metadata path/digest, and observed upstream source-license status. Candidate records are repository-distinct and ordered. They contain no target source, source-snapshot state, human-adjudication state, expected security category, location, plan, answer key, score, readiness state, or model-visible path. Local upstream verification checks the exact pinned metadata record without network access; it cannot promote a candidate into a corpus case. `AcquiredSourcePairSchema` is the separate complete-tree provenance artifact and sole acquired-snapshot state: a valid workspace root contains only its strict manifest plus the declared `vulnerable` and `patched` regular-file trees. Aggregate acquisition validation rechecks every workspace byte/mode and rejects duplicate snapshot or registry/candidate identities; its summaries are content-free and cannot alter candidate, corpus, or readiness state.

`EvaluationRunSchema` version 5 requires run id, pack id/version, corpus-manifest digest, selected-population digest, benchmark-protocol fingerprint, mode, primary provider/model identifiers, verification mode and non-secret verifier-route fingerprint, selected split, optional case selector, answer-key coverage class derived only from the selected cases, evaluator-owned `diagnostic`, `development-pilot`, or `private-holdout` evidence qualification, repetition count, plan profile, measurement scope, strict execution budget, applied vector-concurrency cap, prompt-protocol fingerprint, started/finished timestamps, case outcomes, aggregate metrics, safety violations, and workflow finding-gate status. `ProviderEvaluationCheckpointSchema` version 6 binds the same three identities, selection/profile/scope, route, budget, and vector concurrency before any resumed trial can dispatch. Its command lifecycle is independently `running`, `completed`, `failed`, or `cancelled`: a terminal command error has only the stable source-free `evaluation-run-failed` or `provider-cancelled` code, while individual trial states and scores remain unchanged. Its `PlanScore` is immediate scope reachability only, never semantic plan quality. A trial may retain only aggregate evaluator-only expected-evidence overlap counts for reached neutral mapping, canonical grounding, and verifier output, including after an evaluator failure; those counts are never source locations, model input, scores, or product admission. `PlanSemanticAdjudicationSchema` v1 and its derived `PlanSemanticEvaluationSchema` v1 are separate evaluator-only artifacts: they bind the exact run/trial/case/variant/repetition, generated plan id/digest, target/context fingerprints, and answer-key digest; close the full expected-scenario and enabled-vector sets with a strict bidirectional human outcome; and derive semantic scenario recall, relevant-vector precision, unrelated-vector count, and duplicate-relevant-vector count. A missing, incomplete, stale, or mismatched adjudication exposes unavailable semantic metrics and fails closed; it cannot alter a product report, planning/workflow gate, or provider-quality claim. The qualification is separate from and cannot be inferred from the workflow finding gate. A private-holdout checkpoint and run additionally store one minimal `HoldoutAttestationReference` (attestation id, canonical payload digest, public-key fingerprint, issued-at time). The full strict attestation envelope is source-free and requires schema version, issuer, exact holdout pack id/version/manifest digest, full-readiness-report digest, Ed25519 signature, and matching public-key fingerprint. Before any provider call, the CLI reads regular non-symlink attestation/key files, verifies the key type, manifest binding, and signature; private keys never enter the product. The reference is included in configuration and comparison identities so a changed authorization cannot resume or compare as the same measurement. An optional observed-cost ceiling is intentionally outside the provider-evaluation configuration fingerprint: it is an operational stop condition, not a quality/protocol variable. Resume seeds its ceiling ledger from completed prior-trial observations, permits a changed ceiling, and never compares a ceiling value as quality evidence. Each completed or failed provider trial carries its source-free model usage/cost observation, and the run aggregates it. Completed trials retain the sum of their vector finding-admission funnels: candidates, terminal integrity/verification outcomes, and admitted findings. Finding scoring uses a stable maximum-cardinality one-to-one match between expected findings and actual findings, so overlapping early matches cannot hide later uniquely matchable expected issues. Targeted labels support recall and role-localization only; precision and F1 are null. The execution budget contains model timeout, run timeout, and retry mode; run timeout must be at least model timeout. Metrics are closed objects with explicit nullable fields; persisted evaluation artifacts do not use open records. The comparison contract is closed: a `same-route-regression` rejects changed provider/model, verification mode, route fingerprint, holdout attestation, finding-label coverage, prompt protocol, or vector concurrency; a `primary-model-experiment` allows only the sole primary provider/model and its corresponding same-route fingerprint to differ, requires `same-route` for both artifacts, and retains every other equality check. Comparison output separates adjudicated false-positive and unadjudicated-finding deltas. Neither kind can pass or fail an independent-route experiment without its own preregistered route-compatible baseline.

`ProviderSmokeCheckpointSchema` v1 owns the one-case smoke command lifecycle. It binds run id, provider/model, selected case/variant, target/context fingerprints, reviewed-plan fingerprint, verifier/evidence-map/workflow protocols, and execution budget before audit dispatch. A run id must either start fresh with no checkpoint or resume that exact identity; it cannot overwrite or repurpose stopped work. Its source-free `running`, `completed`, `failed`, or `cancelled` state is distinct from the audited vector outcome. `ProviderSmokeRunSchema` v2 reuses that immutable identity and adds only terminal audit projection, timing, vector summaries, and aggregate model observation; it has no answer key, finding content, source, prompt, tool argument/result, raw model output, or secret.

The real-world corpus answer key is evaluator-only. `CorpusAnswerKeySchema` version 5 carries case-level `staticReviewApplicable`, source-bound expected planning scenarios, `findingCoverage`, and role-specific accepted ranges into every independent review record. An expected planning scenario has a stable id, one-or-more relevant paths, and explicit expected-finding ids; each id must bind to an expected finding on one of those paths. Generated-plan scoring records scope coverage only and cannot claim semantic plan alignment from titles or labels. A `dual-reviewed` key contains exactly two distinct reviewer identities and exactly two human-review records. Both records must be `include` and must match the key's canonical judgment: finding-label coverage, exact scenario set, expected-finding set (id, role ranges, and applicability), patched expectation, and static-review applicability. A qualified dual-reviewed key must be source-only applicable and contain at least one expected vulnerable finding; a non-applicable or no-finding candidate remains provisional or excluded. Every `paired` corpus case must additionally declare `no-matching-finding` for the patched variant before it is evaluable. Reviewer identity, timestamp, notes, and array order do not affect agreement. An optional resolver preserves a disagreement record but cannot turn disagreeing records into a dual-reviewed key. Versions 1–4 are rejected rather than reinterpreted. These records never enter an agent target view, prompt, report evidence, or score input other than through the finalized answer key.

Ground truth is never mounted below the agent target root, included in context files, or passed through a harness tool. The scorer reads it through a trusted evaluator port after the agent run has ended. A pack with a missing, malformed, or target-visible answer key is invalid.
