# Scoped source-inspection recovery

Status: implemented under CAP-050 and CAP-067; amended for exact tool-guided source delivery and context preservation.

The private mixed-language diagnostic run exposed two different workflow signals. Python entered evidence mapping but returned without reading the non-extension source file, so no evidence map could exist. Go produced candidate and verifier evidence in four of five vulnerable trials, but its independent candidate-blind posture contradicted the claim and correctly routed the result to `reviewRequired`; that is a human-review signal, not a basis for automatic promotion.

This change repairs the first class generically. Evidence mapping and source posture with a non-empty scoped path manifest must use `repo_read` or `repo_grep` before completing. The single scoped-stage lifecycle observes only aggregate tool use. If a stage returns without source inspection, it uses the configured normal retry over the identical scope; a repeated or retry-disabled result is the existing `coverage-incomplete` failure. No stage is pre-split, widened, made language-aware, or given a semantic fallback.

The candidate-blind posture instruction also makes the existing independence boundary explicit: a `contradicted` conclusion needs source-visible counterevidence that directly negates the exact approved question or criterion. A declaration, naming convention, parameter, lookup, wrapper, comment, or nearby API call does not establish an effective control by itself. This is an instruction to the model, not a deterministic control detector. Existing provenance validation and the `reviewRequired` disagreement barrier remain unchanged.

The evidence-map and posture instruction changes alter the established prompt-protocol fingerprint. Prior map, posture, grounding, terminal, and provider-evaluation artifacts consequently do not compare or reuse across this revision. A fresh five-repeat diagnostic measurement is required; its results remain diagnostic until the qualified real-world corpus gate is satisfied.

The follow-up structural audit found that the three source-bearing pre-verdict stages could still project whole-file source in a whole-file recovery leaf. That contradicted the tool-guided contract even though the scoped tools and source-inspection gate were mounted. The shared source projection now returns no source package for every initial and recovered scope, and the evaluation-only inline compatibility profile has been removed. The same audit found context parsing and body recovery trimming or normalizing Markdown. Context documents now preserve body whitespace and line endings exactly, recovery chunks concatenate exactly to the original body, and `.md` discovery is case-insensitive. These are transport and provenance repairs only: no parser, static rule, prompt semantic, corpus hint, or admission logic was added.

Verification covers retry-disabled uninspected mapper and posture completions, tool-guided source-package exclusion, exact context reconstruction across CRLF and boundary whitespace, uppercase Markdown discovery, and the existing scoped-tool, retry, source-posture downgrade, unknown-extension, privacy, checkpoint-binding, and provider-evaluation invariants.
