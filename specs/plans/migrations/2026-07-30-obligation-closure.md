# Explicit obligation closure

Status: implementation authorized by the product owner. CAP-069 removes the implicit index-pair coverage model that allowed a vector to be marked complete while some approved review work had no terminal account.

## Decision

Every newly generated attack vector carries a bounded, deliberate set of stable review obligations. An obligation connects one evidence question to one success criterion; it is not a cartesian product generated by implementation code. All later phases reference that exact plan-owned identity.

## Follow-on source-path localization

CAP-070 extends the same evidence-first path with optional entrypoint, root-control, and counterevidence labels. This is additive model context, not a syntax parser or rule catalogue: only a non-null entrypoint reference has a structural map-role check, and a bounded source fragment may explicitly carry no entrypoint. Existing checkpoint reuse is prevented by the protocol fingerprint when agent instructions change; reports remain v6 because their strict source-evidence vocabulary is additively compatible.

## Coverage-aware lineage

CAP-071 adds a post-audit artifact-only lineage projection. It uses the existing exact finding identity only and refuses to turn incomplete coverage into a new, resolved, or persisting claim. It has no target source or model access and does not change finding admission. The separate v1 lineage artifact is generated from current v6 reports, avoiding a report-schema migration.

The audit has four closed phase inputs: scoped vector input, evidence-map input, candidate-blind posture input, and investigation input. Earlier phases cannot receive candidate-shaped fields by construction. Investigation returns one declaration for every approved obligation: `candidate-raised`, `no-source-backed-candidate`, or `incomplete`. It must cite its map/posture basis. Candidate repair may reconcile candidate references but cannot change its security meaning or create a missing closure declaration.

`coverage-closure/` deterministically validates provenance and aggregates content-free state. It does not decide vulnerability semantics, reachability, control effectiveness, or whether no candidate means safe. A row records map state/count, posture state, investigator declaration, candidate/admission counts, and a terminal disposition. Missing, duplicate, cross-vector, out-of-order, or unsupported declarations become visible incomplete coverage. A vector is complete only when all its rows have a terminal closure and no row is incomplete or not reached.

## Migration and recovery

This changes AttackPlan, report, investigation-draft, and terminal-checkpoint contracts. New report artifacts are v6, investigation drafts/checkpoint bindings are v5, and terminal checkpoints are v5. Older artifacts are rejected; they cannot be safely synthesized because their original plan does not contain the authoritative obligation identities. Map and posture checkpoints retain their own version while their binding changes invalidate incompatible reuse.

The report renders the matrix without source text, fact IDs, model output, prompt text, tool data, or raw verdict reasons. Findings retain only already permitted validated redacted source evidence. Evaluation records closure completeness and separate no-candidate from incomplete coverage before any later baseline comparison.

## Non-goals

This is not a language parser, rule catalogue, benchmark exception, second model route, runtime probe, target execution, exploit attempt, patch generator, or a claim that a closed no-candidate row proves a target secure. Entrypoint/root-control/counterevidence enrichment and scan lineage are follow-up capabilities after this invariant is measured.
