# System architecture

Audit is one Bun package with hybrid vertical slices. A feature owns its schema, pure logic, application use case, public exports, and colocated unit tests. Platform folders implement runtime boundaries; shared folders are limited to true cross-feature primitives.

~~~mermaid
flowchart TB
  CLI[CLI] --> FEATURES[Feature use cases]
  FEATURES --> SHARED[Shared strict Zod primitives]
  FEATURES --> PORTS[Feature ports]
  PORTS --> FS[Read-only filesystem]
  PORTS --> H[Purista harness]
  PORTS --> A[Artifact store]
~~~

## Layout

~~~text
src/
  shared/{contracts,errors,observability}
  features/
    target-inventory/{admission,snapshot,index.ts}
    attack-planning/{plan,planner/{agent,stage},index.ts}
    audit-execution/{admission,evidence-map/{agent,stage,index.ts},source-posture/{agent,stage,index.ts},investigation/{agent,stage,index.ts},candidate-grounding/{agent,stage,index.ts},verification/{agent,stage,index.ts},synthesis,index.ts}
    audit-lineage/{contract,lineage,report}
    audit-report/
    model-operations/
    review-workflow/{runtime,tools,instructions,model-contracts,stage-lifecycle,stages/{scoped-model-stage,scoped-evidence},index.ts}
  platform/{configuration,filesystem,harness,artifact-store/{read,write,lease}}
  cli/commands
evaluation/{src,data,runs}
tests/{fixtures,support,integration,e2e}
~~~

No second copy of schemas, enums, path rules, severity rules, or provider contracts is allowed. Feature-specific Zod schemas must be colocated with their feature. Only universal primitives such as ids, timestamps, normalized tokens, common errors, and content-free observability helpers may live in shared/.

Each feature owns a root `index.ts` for its broad public use case. A cross-feature consumer imports only a deliberate facade: the feature root, or a topic's `agent/index.ts`, `stage/index.ts`, or `index.ts` when it needs that narrower surface. No consumer deep-imports an implementation file. Agent facades are construction-safe and export contracts/instructions only; stage facades export invocations separately, so harness construction cannot load executable workflow stages and create a runtime cycle. A topic with an agent keeps its model contract, instructions, invocation/reduction, schemas, and colocated tests below that topic (for example, `attack-planning/planner/`). `review-workflow/` owns only shared lifecycle/tool/runtime behavior and composition, never a topic's semantic policy. An `internal/` subfolder is allowed only when a feature has more than one private implementation concern. Evaluation data is not application source and therefore lives outside `src/`.

## Test placement

Each unit test stays beside the implementation it verifies: thing.ts with thing.test.ts; schema boundary tests use thing.schema.contract.test.ts in the same feature folder. Platform adapter unit tests follow the same rule. The top-level tests directory is reserved for fixtures, shared test support, integration tests spanning real adapters, and end-to-end workflow tests. Do not create central unit or contract test folders.

## Harness graph

Build only with defineHarness() in dependency order: telemetry/logger, explicit sandbox, defaults, models, tools, skills, agents, workflows, build. v1 uses inMemorySandbox() with no executor, NO_CONTENT telemetry, planning/evidence-map/source-posture/investigation/candidate-grounding/verification agents, custom `repo_list`/`repo_read`/`repo_grep` tools, and no built-in tools. The review-workflow `tools/contract` feature single-owns those model-facing schemas, identifiers, descriptions, and inferred types; `review-workflow/runtime` adapts the immutable source-snapshot port to that one contract, selects applicable advisory context, and owns normal retry plus provider-signalled context-overflow recovery; `review-workflow/stages/scoped-model-stage` single-owns the common scoped lifecycle, tools, source-inspection protocol, and content-free ledger; each topic feature owns its agent contract, instruction, workflow call, and typed reduction. The platform harness only mounts topic-feature contracts, and the service composes planning plus audit stages. The planner is scoped to the complete admitted snapshot manifest and must `repo_read` or `repo_grep` before it can return a draft; every audit stage receives a vector-scoped allowlist. File-tool telemetry stores aggregate call kinds, returned-byte total, and recovery state only; it stores no path, pattern, argument, response, partition, or source content. `repo_grep` supports literal, identifier, and safe-regex modes; identifier mode uses language-neutral identifier boundaries (`A–Z`, `a–z`, `0–9`, `_`, `$`) to prevent substring noise. Workflow orchestration, plan sealing, vector fan-out, verification, recovery, and reporting remain feature use cases rather than agent code. The CLI composes the audit-execution-owned `cli-persistence` adapter: it single-owns exact checkpoint binding construction, validated private-work recovery reads, retained-observation aggregation, and durable audit-stage callbacks. `src/cli/main.ts` is the process boundary only: generic parsing, configuration, root preparation, provider construction, and typed dispatch. Exactly four command facades own lifecycle orchestration: `commands/planning` (`plan`, `plan-draft`, `plan-reseal`), `commands/audit` (`audit`, `discard`, exact-run recovery), `commands/guidance`, and `commands/reporting` (`report`, `lineage`). Command facades receive dependencies from `main.ts`, never import it, and use feature-root facades. The CLI must not recreate checkpoint paths, binding literals, callback writers, or resume-array assembly.

`platform/harness/` single-owns declared provider structured-output capability profiles and their pure JSON-Schema compatibility validation. Every live model-output contract is checked against its selected route before target I/O, provider construction, checkpoint/artifact work, or dispatch; an undeclared or incompatible profile fails closed. Feature agents continue to own canonical semantic contracts. A provider-only root-object envelope is allowed only as a lossless transport adapter around one canonical result, and the owning stage unwraps it once before feature materialization; envelopes never enter findings, reports, checkpoints, scoring, or semantic admission. The shared scoped lifecycle may send an allowlisted failure diagnostic event only to an explicitly enabled evaluator-private sink; product commands retain the existing no-content boundary.

Tools return only relative paths, positive line numbers, complete requested results, and stable error codes. The current read-only adapter has no result paging or fixed source, line, match, or tool-call cap. If a future transport needs paging, its cursor and completeness metadata must support automatic exact continuation until the requested scope is complete or explicit incomplete coverage. Tools never accept shells, absolute paths, URLs, file descriptors, executable code, HTTP requests, or live-target identifiers. Repository source and optional context are separate labeled evidence classes; context cannot authorize a tool or override source evidence.

Language identification is a feature-owned best-effort hint inferred from a relative filename. The filesystem jail, inventory, prompts, source-evidence schema, plan schema, and report schema must accept a null/unknown hint. No extension, parser, language enum, AST node kind, or static rule may be used as a target-file allowlist or as finding admission evidence. An unavailable semantic aid contributes an explicit coverage limitation, never a language-wide rejection.

The audit feature owns the complete static-review pipeline: `evidence-map/` owns neutral map integrity; `source-posture/` owns a candidate-blind per-obligation source assessment; `investigation/` owns language-neutral bounded hypothesis discovery and obligation closure; `candidate-grounding/` owns seed-to-canonical-candidate pairing; `verification/` owns an independent challenge of a canonical hypothesis; `coverage-closure/` owns terminal state derived from the append-only phase ledger; `admission/` owns content-free outcome accounting; and `synthesis/` owns deterministic duplicate collapse and source-supported chain construction. The posture input excludes candidates, findings, classification or urgency labels, fixes, verdicts, answer keys, and paired variants; discovery produces no reportable finding; grounding cannot create a hypothesis. Each module consumes the feature-owned Zod contracts rather than defining parallel shapes. Language hints can improve an explanation but cannot suppress inspection, determine a security operation, or create a complete-coverage claim. `03-architecture/08-reliable-terminal-coverage-and-resume.md` owns final phase/coverage and resume semantics.

`audit-lineage/` is a post-audit, artifact-only feature. It consumes two validated reports and the single-owned deterministic finding identity; it owns no target read, provider, model, parser, or evaluation answer key. It marks unmatched findings new/resolved only when the matching vector completed in the other report, otherwise preserves `unknown`. Its source-free artifact is separate from evaluation-run comparison, which has different comparability and metric semantics.

In this architecture, historical uses of “approved plan” and “human approval” mean a valid, externally editable plan that the product has validated and resealed. The product stores no approval state and must not require an approval artifact or bypass; the executable plan alone is the audit authority.

The production finding path is language-neutral and candidate-blind. After a valid sealed plan is supplied, neutral mapping is followed by a fresh source-posture assessment for each approved risk-positive obligation; only then may discovery list, read, and search the vector scope and emit a non-reportable seed or an explicit closure. Discovery and grounding model contracts never author posture identifiers: the source-posture feature derives each canonical posture identity and its already-backed map facts once from the exact approved obligations. Canonical grounding can turn a valid seed into a structured candidate only when it preserves the seed's exact vector, obligation, and map identity, and carries that derived posture provenance forward. It selects complete operation and unsafe-condition evidence bundles only by fact identifier and evidence index from that already selected neutral-map basis; deterministic code projects every exact source location rather than accepting model-authored paths, lines, snippets, or roles. Canonical admission validates provenance, not security semantics. Every hypothesis names the vector, identifies the claimed unsafe condition, cites complete evidence bundles, states limitations, and cites the derived posture assessments with their included map facts. A posture conclusion is evidence context, never a deterministic `risk-supported`-only veto. A separate verifier receives that bounded hypothesis and independently inspects only the same vector scope. It must accept, reject, or mark the claim incomplete; it may not create a new finding. An accepted verifier output selects complete operation/unsafe-condition bundles, control, and one non-unresolved reconciliation for every exact hypothesis obligation by map fact and evidence index; each obligation selection must come from a fact bound to that same approved obligation. A rejected output selects source-backed contradiction evidence; an incomplete output has a closed gap reason and no security conclusion. Deterministic code projects those locations, exact obligation coverage, posture provenance, and every relevant mapped control identifier. It checks only sealed-plan identity, scope, selected evidence, path/line existence, role shape, exact source-content-digest projection, map/posture/obligation provenance, required control-fact coverage, redaction, phase identity, and state transitions. It never decides that a lexical match, API name, parser node, language extension, or benchmark pattern is a security operation or a data flow. A synthetic source-flow pointer is neither evidence nor an admission criterion. An accepted claim requires both valid deterministic evidence integrity and a completed verifier acceptance. Rejected and incomplete claims remain measured outcomes, never findings. This prevents a first-pass model from making its own unsupported interpretation authoritative without embedding a language-specific rule catalogue in the product.

Model cost resolution is a separate operational concern. `features/model-operations/` resolves only exact normalized provider/model pairs from a generated, checked-in LiteLLM price snapshot plus documented exact supplemental entries. `.env` and CLI flags never accept price values, and plan/audit/evaluation commands never fetch prices. The contributor-only refresh command may download the upstream catalogue, reports changes before writing, and produces a deterministic snapshot. Unknown entries stay explicitly unavailable, preserving truthful source-free cost records without coupling target analysis to pricing.

Current production uses one configured model route for investigation and verification. CAP-063 implements an optional, separately configured verifier route only in provider evaluation to test whether route diversity reduces same-route confirmation bias. Product commands reject it and a qualified, preregistered real-world comparison is required before it can affect product admission.

No AST or parser adapter is part of the production finding path in this version. A future syntax service may be specified only as a reusable, multi-language navigation/enrichment port that emits no security conclusion and cannot affect planning, finding admission, classification, urgency, or scope. It requires a separate dependency, supply-chain, language-coverage, and corpus-independent design decision.

`model-operations/` owns provider-response usage capture, cost calculation, provider-side prompt-cache routing metadata, and source-free observations. Every model-backed planning, evidence mapping, source posture, discovery, candidate grounding, verification, and isolated evaluation stage creates one independent observation before a run aggregate is derived. Audit vector coverage stores these independently, and the run aggregate is derived only from retained observations. It records tokens, cache routing, latency, cost state, and aggregate-only file-tool usage; it never persists requests, prompts, source, tool arguments, secrets, provider request ids, or raw responses.

`model-operations/` owns source-free model usage and catalogue-derived cost telemetry shared by planning and audit stages. It never gates dispatch or bounds source, context, tool use, output, or audit work. Resume deduplicates matching retained observations only when deriving telemetry so checkpointed work is not counted twice.

The source-admission policy and snapshot builder own every target byte that can reach a model; target inventory, source tools, target fingerprinting, checkpoint binding, and plan sealing consume that one snapshot identity. Provider-output compatibility validation precedes that target boundary and has no target, source, context, artifact, or provider side effect. Root topology, atomic artifact writes, run ownership, and terminal-state derivation are owned by `03-architecture/09-immutable-evidence-and-terminal-truth.md`; no feature may recreate them.

Independent vectors enter a configured rate-limit queue; the concurrency setting limits only simultaneous work, and every enabled vector remains required before the plan-order merge. Every vector receives only paths matched by its approved `scopeGlobs` and separately labelled applicable context. Discovery, grounding, verification, and the isolated countercheck explore with complete scoped tools: no fixed product file, source path, line, search-match, returned-byte, source-package, tool-call, context-document count/size, or language-specific ceiling may omit approved evidence. Only a normalized provider `context_length_exceeded` starts deterministic recovery partitioning; estimates never do. The shared order is source paths, source newline ranges, then applicable context documents/body newline ranges, all in stable order and held only in memory. A non-lossless reduction becomes visible incomplete coverage rather than an implicit evidence cut. Cancellation propagates AbortSignal and closes resources. No checkpoint is written inside the target. The CLI atomically checkpoints a validated evidence map, candidate-blind posture, and canonical candidate-grounding draft below private work; the grounding draft contains exactly one canonical outcome per seed plus its complete source-free funnels, rejection ledger, and required stage observations. It writes the terminal vector-result checkpoint after verifier resolution below private work and publishes only `PublicAuditReportSchema` plus a source-minimal run manifest below the separate public artifact root. Discovery seeds and raw grounding input/output are not checkpointed. A matching grounding draft is itself a recovery boundary, even if no later candidate-aware checkpoint exists: the audit derives durable grounded candidates and predecessor telemetry from it, then uses the normal candidate-aware lifecycle to schedule the smallest unfinished unit. Only an outcome explicitly defined as unfinished seed work may restart at its own earlier exact boundary. Every reuse remains bound to the immutable run, plan, target, route, protocol, map, posture, vector, and candidate identities.

Evidence delivery is tool-guided without a profile switch: the agent receives the approved vector, a complete scoped path manifest, labelled context, and no source package. This projection applies to the initial scope and every recovered path, range, or context leaf. `repo_read` returns exact physical `{line,text}` records, so the evidence mapper returns only a strict fact identifier, neutral role, statement, approved-obligation references, and `{path,startLine}` selections whose lines were actually returned by the tool; a model never estimates coordinates from unnumbered source text. Canonical provenance projection—not the model—derives the evidence content digest, kind, and optional end line without persisting source text. Every source-deciding phase (evidence mapping and candidate-blind posture) with a non-empty scoped manifest must use scoped `repo_read` or `repo_grep` before returning, even when it intends to report incomplete coverage; `repo_list` alone is not source inspection. `repo_grep` can locate a candidate area but cannot itself justify an exact source-evidence selection. The common scoped lifecycle observes this protocol without interpreting source text. An uninspected completion uses the existing normal retry over the identical scope when retries are enabled; a repeated or retry-disabled failure becomes visible `coverage-incomplete`, never a static fallback or a clean conclusion. This gives the audit and every evaluation a deliberate, inspectable repository-exploration loop without a language-specific prefilter. Tools must never expand to the repository root, context root, answer keys, or another vector.

Artifact writes go to separate public-artifact and private-work roots via temporary file plus atomic rename. Mutable run/checkpoint records may replace their prior version under their exclusive owner lease in private work. Published plan JSON, plan Markdown, and editable plan drafts are private-work artifacts and use the separate create-only publication primitive: an existing destination fails closed and cannot be replaced. Public report/lineage artifacts are source-minimal projections. Raw prompts, tool payloads, and full source files are not persisted.

The evaluation workflow uses trusted local code to score validated artifacts. The agent never receives answer keys, expected locations, or scoring code. Evaluation runners use a separate read-only benchmark root and write only to an evaluation run directory.
