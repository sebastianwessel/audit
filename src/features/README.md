# Features

A feature folder is the primary ownership boundary. Place schema, inferred types, pure rules, application orchestration, public exports, and unit tests together. Every feature root owns an `index.ts`; cross-feature, platform, CLI, and evaluator imports use either that facade or a deliberate topic facade (`index.ts`, `agent/index.ts`, or `stage/index.ts`), never an implementation file. Agent facades expose only construction-safe contracts and instructions; stage facades expose executable invocations separately. Group a model-backed step's contract, instructions, stage, schemas, and tests under one topic folder. `review-workflow/` is reserved for reusable tool, runtime, lifecycle, and composition code; it does not own a topic's semantic agent policy.
